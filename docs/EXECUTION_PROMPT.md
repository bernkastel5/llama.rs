# Промпт на исполнение

> Скопировать целиком в новую сессию, когда решение принято. Он самодостаточен:
> не требует контекста предыдущего обсуждения.

---

Ты работаешь в репозитории `llama.rs` — CPU-only инференс LLM на Rust, цель проекта:
работать быстро на слабых ноутбуках. Ветка: `arena/01a032d4-llama-rs`.

## Цель

Поднять скорость генерации с текущих ~30–40% от llama.cpp до **≥80%**, сохранив
возможность масштабирования на новые архитектуры, форматы весов и виды взаимодействия.

## Методология: бережливое производство

* **Поток единичных изделий** — один проход по весам на единицу работы. Любое место,
  где веса читаются из памяти дважды, — дефект.
* **Jidoka (встроенное качество)** — тест паритета пишется ДО оптимизации, не после.
  Оптимизация без теста паритета не принимается, даже если она быстрая.
* **Стандартизованная работа** — бенчмарк перед изменением и после, цифры в коммит.
  Изменение без цифры — не улучшение, а гипотеза.
* **Кайдзен-поток** — одно изменение за коммит. Не смешивать шаги.
* **Устранение перепроизводства** — не обобщать под несуществующие требования.
  Сначала выйти на цель на одной модели, потом расширять.

## Обязательное чтение перед началом

`docs/PERF_PLAN.md` — полный анализ с измерениями. Там же список того, чего делать НЕ надо.
Ключевое, что нужно усвоить сразу:

* Задача **memory-bound**: крыша памяти 5.8 ГБ/с (1 поток) / 10.7 ГБ/с (2 потока).
* Текущее f32-ядро выдаёт 1.8–2.4 ГБ/с → упирается в ALU, потенциал ~3×.
* int8-ядро выдаёт 4.8–10.2 ГБ/с → у крыши. Это цель, дальше расти некуда.
* **AVX-512/VNNI даёт 0.82–1.00×.** Измерено. Не тратить на это время.

## Порядок работы — строго по шагам

Каждый шаг: сначала бенчмарк baseline, потом тест паритета, потом реализация, потом
бенчмарк после, потом коммит с цифрами в сообщении. Не переходить к следующему шагу,
пока предыдущий не измерен.

**Шаг 0 — инфраструктура измерений.** (частично готово: `llama-bench` + `scripts/track.sh`)
`.cargo/config.toml` с `target-cpu=native`; `lto = "fat"` в release-профиле;
`criterion` в dev-dependencies; бенчи на matvec (формы 896×4864, 4864×1024, 151936×896),
attention (ctx 256/1024/4096), полный шаг декодирования. Тесты паритета для каждого
существующего ядра против скалярной референсной реализации. Baseline → `docs/BASELINE.md`.

**Шаг 1 — Q8_K-активации и int8-ядра.** Ожидание 2.4–5.7× на matvec.
Квантовать активацию в Q8_K один раз на matvec (не на строку!), ядра на
`_mm256_maddubs_epi16` с одной редукцией на строку вместо `hsum` внутри блока.
Квантованная активация — отдельный тип, передаваемый ядру по ссылке.

**Шаг 2 — persistent-воркеры + spin-барьер.** Ожидание −8.4 мс/токен.
`par_iter_mut` на каждый matvec = ~168 fork-join-барьеров на токен по 50 мкс.
Spin-барьер стоит 0.11 мкс. Пул живёт весь шаг декодирования.

**Шаг 3 — векторизованный attention.** Ожидание 4.6–11.3×.
AVX2 для Q·Kᵀ и weighted-V, параллелизм по головам через пул шага 2, SIMD-softmax.

**Шаг 4 — батч-GEMM prefill.** Ожидание 1.56×…2.23× при N=4…32.

**Шаг 5 — f16 KV-кэш за флагом.** 2× при ctx=4096, вдвое меньше ОЗУ. Не раньше шага 3.

**Шаг 6 — хвост.** SIMD RMSNorm/SwiGLU, таблица inv_freq вместо `powf` в RoPE,
`select_nth_unstable` вместо полной сортировки 151936 логитов, `VecDeque` вместо
`Vec::remove(0)`, F16/BF16-ядра, потоковая load-time квантизация.

**Шаг 7 — масштабирование, только после достижения ≥80%.**
Декларативная weight-map вместо захардкоженных имён тензоров; правила квантизации от
описания архитектуры, а не от подстрок в имени; диспатч ядра один раз при загрузке,
а не на каждой строке.

## Инвариант архитектуры

**Абстракция снаружи горячего цикла, мономорфизация внутри.** Trait-объект на уровне
слоя бесплатен. Trait-объект или рантайм-диспатч на уровне строки матрицы съедает всю
производительность. Если новое обобщение добавляет ветвление внутрь цикла по строкам —
оно сделано неправильно.

## Definition of Done для каждого шага

1. Тест паритета зелёный (новое ядро ≡ референс в пределах допуска).
2. `cargo bench` до/после, цифры в сообщении коммита.
3. Существующие тесты не сломаны.
4. Изменение изолировано — один шаг, один коммит.
